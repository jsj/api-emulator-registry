Run `npm run parity` to replay captured upstream scenarios locally. The command writes a JSON report to `.emu/parity/robinhood-trading.json` and makes no network calls. `npm run parity -- --json` prints the complete report.

The report separates declared contract coverage from behavior evidence. Each operation is missing, unverified, partial, or verified in bounded scenarios. Passing a few scenarios does not establish full parity. Offline contract comparison checks the saved declaration; the emulator uses that same contract fixture, so this alone is not independent upstream validation.

Run `npm run parity -- --live-contract` to compare all saved tool names, descriptions, input schemas, and output schemas against authenticated upstream `tools/list`. This uses local mcporter authentication, has a 90-second timeout, and fails if authentication or the request fails. It never calls live tools. An offline run explicitly reports the live contract as not checked. Capture timestamps remain unchanged by replay.

To refresh behavior evidence, run `node providers/@robinhood-trading/scripts/capture-parity.mjs`. Its hardcoded allowlist permits only public `get_currency_pairs` and `get_indexes` reads. It saves separate baseline catalog reads and argument scenarios, writes raw responses privately under `.emu`, and replaces the public fixture only after all calls succeed. Review fixture changes before accepting them; recapture does not update the contract or gap ledger. It never calls accounts, previews, orders, or cancellations.

The first five scenarios exercise currency-pair limits and index symbol filters. Baseline catalogs seed the emulator; expected responses come from separate live calls. Only opaque pagination URL values are ignored, with reasons in the fixture. Missing fields, extra fields, types, array order, lengths, and all other values remain checked. Response `data` is compared; guide prose, HTTP/MCP transport behavior, error responses, cursor traversal, changing prices, and write behavior are outside this pilot's evidence.

`fixtures/parity-gaps.json` records exact observed differences with reasons. A known gap remains partial and never counts as verified. New differences, changed differences, and even resolved gaps fail the regression check until the ledger is reviewed. `npm run parity -- --strict` fails on any gap in the selected scenarios. Strict mode still does not require every advertised operation to have evidence.

CI runs offline replay on pushes and pull requests and uploads the report. It checks regressions against the dated capture, not current upstream freshness. Authenticated live drift checks run explicitly on a machine with credentials; no credentials are required by CI.

To extend this to another emulator, add an adapter to the provider map in `scripts/parity.mjs`. The adapter supplies expected and actual operation declarations, independently captured cases, seed state, and `runScenario`. Start with representative filtering, pagination, and error cases. Test mutations only locally or in an explicitly authorized sandbox. Keep unsupported operations unverified and record gaps instead of assigning subjective parity percentages.
